2. Skew-t vs. symmetric-t: the in-sample LR test (necessary, not sufficient)¶

Hansen's (1994) skewed Student-t, nested over symmetric-t at λ=0. Same monotonicity discipline as Milestone 2's LR tests: the unrestricted (skew-t) log-likelihood must be ≥ the restricted (symmetric-t) log-likelihood at the true optimum, checked before trusting the result.

from scipy.stats import chi2

def kupiec_test(violations, level):
    n = len(violations); x = violations.sum()
    pi_hat = x/n
    ll_null = x*np.log(level) + (n-x)*np.log(1-level)
    ll_alt = x*np.log(pi_hat) + (n-x)*np.log(1-pi_hat) if 0 < pi_hat < 1 else 0
    lr = -2*(ll_null-ll_alt)
    pval = 1-chi2.cdf(lr, df=1)
    return {'n':n,'violations':int(x),'rate':round(pi_hat,4),'pval':round(pval,4)}

for name, df in [('symmetric-t', symt_wf), ('skew-t', skewt_wf)]:
    print(f'--- {name} ---')
    for lvl, col, target in [(0.05,'VaR_95',0.05),(0.01,'VaR_99',0.01)]:
        viol = (df['realized_return'] < df[col]).values
        print(f'  {col}:', kupiec_test(viol, target))

5. Mechanism decomposition: is it actually skewness?¶

The easy, clean claim — "skewness fixed the coverage gap" — was available and would have gone unquestioned. Checked against ν (degrees of freedom) at each of the three flipped refit windows, since a free extra parameter in a walk-forward refit can shift where OTHER parameters land too, not just the one it was added for.

In [8]:

Refits 8 and 18: ν barely moves (−0.10, −0.30), λ does the work — cleanly attributable to skewness. Refit 10: ν drops by over 2 full points (7.22 → 5.09) alongside λ — a joint effect, the base tails getting fatter overall AND becoming asymmetric, not skewness in isolation.

Honest conclusion, not the cleaner one: the coverage improvement is mostly, not purely, attributable to skewness — 2 of 3 flips support the mechanism cleanly, 1 of 3 doesn't isolate it. Recommending adoption on this basis. This matters beyond this milestone: anyone tuning this model later who assumes the improvement is pure-skewness and looks only for skewness-shaped explanations for future misses would be missing that the tails-getting-fatter mechanism is also demonstrably live in this data.

6. ML challenger: pre-registered criterion, decided before fitting¶

Model: LightGBM, two specifications — variance regression (squared-return target, for QLIKE) and direct quantile regression at α=0.05/0.01 (for VaR, no parametric distributional assumption). Same walk-forward window and quarterly refit cadence as the GARCH specs, for a fair comparison.

Win condition, fixed before any model was fit: beats GJR-GARCH skew-t (champion) on out-of-sample QLIKE, AND does not fail Kupiec calibration where the champion passes.

Business Insights¶

  1. Skew-t is adopted for UBSG, closing the Milestone 2 coverage gap (Kupiec p: 0.014 → 0.079) — verified via a paired day-by-day comparison (0 unfavorable flips, no clustering) and a mechanism decomposition that stopped short of the cleaner "pure skewness" claim the data didn't fully support (2 of 3 flips clean, 1 of 3 a joint ν/λ effect).
  2. The ML challenger does not replace the champion, per a rule fixed before fitting — a genuine QLIKE and 95%-calibration win, disqualified by failing 99% Kupiec exactly where the champion passes. Retained as a monitored alternative, not a rejected dead end.
  3. Both results depended on deciding the evaluation rule before running the model — the skew-t success criterion (LR/AIC necessary, backtest coverage sufficient) and the ML win condition (QLIKE plus calibration, not either alone) both did their job specifically because they were fixed in advance, not fit to whichever result looked best afterward.

Lessons Learned¶

  • A statistically significant LR/AIC result is a necessary check, not a sufficient one — skew-t's in-sample fit improvement had to be verified against actual walk-forward coverage before being trusted as "fixed."
  • Two univariate test results moving in opposite directions across a threshold is not proof of a real difference — a paired, day-by-day comparison of exactly which observations changed is the check that actually establishes whether an improvement is general or an artifact of a few specific days.
  • Adding a free parameter to a walk-forward-refit model can shift other parameters, not just the one it was nominally added for — attributing a result to "the new parameter" without checking the others is the same shape of unearned confidence as any other unverified mechanism claim this project has caught.
  • A pre-registered win condition only works if it's honored when the result is inconvenient — the ML challenger's QLIKE win was the more interesting-sounding result; the rule, fixed in advance, is what kept that from becoming the headline over a real 99%-coverage failure.
  • A fix from an earlier milestone that lives in a one-off command doesn't survive an environment reset — the mkdir brace-expansion error recurred because the original fix wasn't saved as a script. Now it is.

Limitations¶

  • Skew-t's mechanism attribution rests on a 3-observation paired sample (the flipped days) — directionally clear, not a large-sample statistical claim on its own.
  • ML challenger uses a single feature set and default-adjacent LightGBM hyperparameters — not a tuned or feature-searched model; the QLIKE gap could plausibly close or widen with more development effort in either direction, untested here.
  • Both this milestone's findings inherit Milestone 2's standing caveats (short post-merger UBSG sample, deferred event-clustering methodology) — addressed separately in the standing open-threads note per instruction, not repeated in full here.
